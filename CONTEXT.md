## Objective

Create a portfolio website with Astro 7, hosted on Cloudflare Workers, that updates nightly. A scheduled **GitHub Actions** workflow pulls repository data from the GitHub GraphQL API, rebuilds the site, regenerates the PDFs and deploys. The **Cloudflare Worker** only serves the prebuilt static files. It runs no code and does no updating.

The site's job is to put every claim one click from its evidence: skills link to projects, and projects link to repos, demos and case studies.

The owner is a test architect. The test suite and CI are part of the portfolio: first-class deliverables, not afterthoughts.

### Known traps

These were verified against the pinned versions. Do not "fix" them another way.

| Trap | Do this |
|---|---|
| `TODO(owner): x` unquoted is invalid YAML | Always quote: `summary: "TODO(owner): x"` |
| `<` and `{` in an MDX body are parsed as JSX | Never use `<`, `>`, `{` or `}` in placeholder text |
| A broken `reference()` logs an error but the build exits 0 | `check-content.ts` enforces references (rule 1) |
| `.extend()` throws when it overwrites a field on a schema that has refinements | No `.refine()` or `.superRefine()` on object schemas in `lib/schemas.ts`. Field-level checks are fine. Cross-field rules live only in `integrity.ts` |
| `file()` treats each top-level key as an entry, and a missing file only logs an error | Use the `parser` shown under [Collections](#collections) |
| The default `glob()` id strips dots | Set `generateId` as shown under [Collections](#collections) |
| When an AI agent runs `astro preview` or `astro dev`, Astro starts it in the background and exits | Never spawn the CLI from code. `render-pdfs.ts` uses `import { preview } from 'astro'`. For manual runs, set `ASTRO_DEV_BACKGROUND=0` or `ASTRO_PREVIEW_BACKGROUND=0` |
| `astro preview` does not match Cloudflare's redirects or 404s | Browser tests run against `wrangler dev` |
| Vitest collects Playwright specs by default | Vitest `include: ['tests/unit/**/*.test.ts']`. Playwright files end in `.spec.ts` |
| `exifr` throws on WebP and SVG | Source images may only be `.png`, `.jpg`, `.jpeg` or `.svg`. Skip SVG in the GPS check |
| `new Date('2026-03')` is UTC and can display as February | `dates.ts` works on strings and never constructs a `Date` |
| Astro 7 removes whitespace between inline elements across lines | Add `{' '}` in `.astro` templates where a space is needed |

## Content schemas

Field rules are plain Zod objects in `src/lib/schemas.ts`, where references are `z.string()` ids and image fields are relative-path strings. Export the inferred types (`ProjectData`, `ExperienceData`, `SkillData`, `MilestoneData`, `TrackData`, `SiteData`, `GitHubSnapshot`), and:

```ts
export interface Entry<T> { id: string; data: T }
```

`content.config.ts` extends these schemas with `reference()` and `image()`.

**Dates:** every date field accepts `YYYY-MM` (month 01–12) **or** a string starting with `TODO(owner)`. A placeholder displays as "Date TBD", sorts as the oldest date, and fails strict content mode. An absent `end` means ongoing.

## Library contracts

All of `src/lib/` is pure: no Astro imports except `astro/zod`, and no filesystem or network access.

```ts
// dates.ts
isPlaceholderDate(d: string): boolean
compareDates(a: string, b: string): number            // ascending; placeholders are oldest
formatDate(d: string): string                         // "2026-03" -> "Mar 2026"; placeholder -> "Date TBD"
formatPeriod(p: { start: string; end?: string }): string // "Mar 2026 – Present"

// rank.ts
rank(projects: Entry<ProjectData>[], trackId: string): Entry<ProjectData>[]

// evidence.ts
skillsForTrack(skills, projects, trackId): SkillWithEvidence[]
skillsForProject(skills, projectId): Entry<SkillData>[]

// integrity.ts
interface ContentSet { projects; experience; skills; milestones; tracks } // each Entry<T>[]
interface ImageFile { path: string; bytes: number; hasGps: boolean }      // repo-relative, forward slashes
interface RawFile { path: string; text: string }
interface Violation { rule: number; file: string; message: string }
checkContent(c: ContentSet): Violation[]      // rules 1-6, 8, 9, 12
checkFiles(images: ImageFile[], allPaths: string[]): Violation[] // rules 10, 11
checkStrict(files: RawFile[]): Violation[]    // rule 7
```

- **rank:** the track's non-draft projects, ordered by featured first; then ongoing first; then `period.end` newest first; then `period.start` newest first; then id ascending.
- **skillsForTrack:** a skill belongs to a track when at least one of its evidence projects is a non-draft project in that track. Return only that track's evidence. Order by category, then name.
- **experience order**, everywhere: current roles first, then `start` newest first, then id.
- **Content adapters:** pages map Astro entries to these plain shapes (references become id strings) in `src/lib/adapt.ts`.

## Integrity rules

`scripts/check-content.ts` accepts `--root <dir>` (default: the working directory). It validates every raw file against its Zod schema, runs every rule, prints all violations, and exits 1 if there are any. It runs before `astro build`.

Each rule has at least one valid and one invalid unit test. The invalid test must report that rule's number.

1. Every reference resolves to an existing entry. This includes one test that runs the script on a temporary content tree and expects exit code 1.
2. Exactly one track has `default: true`.
3. Every track has at least `MIN_PROJECTS_PER_TRACK` non-draft projects (a constant, 1 for now; the owner raises it to 3 at launch).
4. A repo-backed project's id equals its repository name, lowercased.
5. `confidential: true` means no `repo` and no `demo`.
6. Skill evidence points only to non-draft projects.
7. **Strict content mode:** when `STRICT_CONTENT=true`, no file under `src/content/` contains `TODO(owner)`. Off for the skeleton.
8. A set `cover` has a non-empty `coverAlt`, and every `gallery` item has a non-empty `alt`.
9. Every frontmatter image lives in `src/assets/projects/<that project's id>/`. MDX-body images are not checked in the skeleton.
10. No image under `src/assets/` or `public/` contains GPS metadata.
11. Images under `src/assets/` and `public/` are only `.png`, `.jpg`, `.jpeg` or `.svg`. No image under `src/assets/` or `public/` exceeds 5 MB. No `.mp4`, `.mov`, `.webm` or `.mkv` exists under `src/` or `public/`.
12. `experience.projects` points only to non-draft projects.

Binary fixtures (GPS JPEG, oversized image, empty `.mp4`) are generated into a temporary directory at test time. Never commit them.

## GitHub data (`scripts/fetch-github.ts`)

- **Input:** the distinct `repo` values of non-draft projects, read through `scripts/lib/content.ts`. With none, skip the request and write an empty `repos` object with `source: "live"`.
- **Request:** one GraphQL query with one alias per repository. Fetch `nameWithOwner`, `isPrivate`, `description`, `url`, `homepageUrl`, `primaryLanguage { name }`, the top 5 `languages` by size, `stargazerCount`, `pushedAt`, `isArchived`, and the default branch's latest `committedDate` and `statusCheckRollup { state }`.
- **Nullable:** `description`, `homepageUrl`, `primaryLanguage`, `pushedAt` and the default branch may be null. The schema and the card must handle that. A null rollup becomes `"none"`.
- **Auth:** the `GH_GRAPHQL_TOKEN` environment variable.
- **Output:** `src/data/github.json` as `{ fetchedAt, source: "live" | "cache" | "fixture", repos: { "<owner/name>": {...} } }`, with sorted keys.
- **Fixture:** `tests/fixtures/github.json` contains `Nels27/AgentsOfOlympus` and `Nels27/Portfolio-Website`, with obviously synthetic values (0 stars, fixed timestamps, `"none"` status) and a null `primaryLanguage` for the second.
- **Testability:** export a function that takes `fetch`, the token, paths and the clock as arguments. Unit tests use a fake `fetch` and cover every row below.

| Condition | Result |
|---|---|
| No token | Copy `tests/fixtures/github.json` with `source: "fixture"`, warn, exit 0 |
| HTTP 401 or bad credentials | Exit 1: the token expired or is wrong |
| `NOT_FOUND` for a listed repo | Exit 1: it would be a broken link |
| `isPrivate: true` | Exit 1: visitors couldn't open the link |
| `FORBIDDEN` on `statusCheckRollup` only | Use `"none"`, warn, continue |
| Network error, HTTP 5xx, HTTP 429, or a rate-limit response (including HTTP 403 and `RATE_LIMITED`) | Keep the existing file, keep its `fetchedAt`, set `source: "cache"`, warn, exit 0. With no existing file, use the fixture |
| Any other GraphQL error | Exit 1 |

A project whose repo is missing from the snapshot renders a plain repository link instead of a card.

## PDFs (`scripts/render-pdfs.ts`)

After `astro build`, the script:
1. Starts the built site through Astro's `preview()` function on a local port.
2. For each track, opens `/resume/<slug>/` in Chromium and writes `dist/resume/<slug>.pdf`. Then opens `/cv/` and writes `dist/cv.pdf`. Uses `page.pdf({ preferCSSPageSize: true, printBackground: true })`.
3. Closes the browser and server in a `finally` block.

It fails if a page does not return 200. `print.css` sets `@page` to US Letter. Résumés are at most 2 pages. The CV has no page limit.

## Workflow: branches and quality gates

### One branch per task

1. Start from an up-to-date `main`: `git switch main && git pull && git switch -c task/NN-short-name`.
2. Do only that task. Write tests first.
3. Run every gate that exists so far, locally, and confirm each passes.
4. Commit with Conventional Commits, push the branch and open a PR to `main`. If `gh` is unavailable, push and report the compare URL.
5. The PR description lists what was built, the gate output, any defaults relied on and any open question.
6. **Stop.** The agent never merges, never pushes to `main` and never starts the next task until the previous PR is merged.

### Gates

A PR merges only when all of these pass:

| Gate | Check | Enforced by | Added in task |
|---|---|---|---|
| G1 | `npm ci` from the lockfile | CI | 01 |
| G2 | `npm run check`: 0 errors | CI | 01 |
| G3 | `npm run test:unit` | CI | 01 |
| G4 | Coverage of `src/lib/` at or above 90% for lines and branches | CI | 02 |
| G5 | `npm run build`, including content integrity | CI | 05 |
| G6 | `npm run test:e2e`: routes, links, headers, no client JS, no CSP errors | CI | 07 |
| G7 | `npm run pdf`, plus PDF text and page-count tests | CI | 09 |
| G8 | axe: no serious or critical violations | CI | 10 |
| G9 | Code review on a stronger model (Opus): no unresolved correctness finding | Owner | 01 |
| G10 | Owner reads the PR and squash-merges | Owner | 01 |

- G1–G8 run in one job named **`quality-gate`**, which is the required status check. The name never changes.
- The steps live in `.github/actions/quality-gate/action.yml`. `pr.yml` and `main.yml` both use it, so a PR and a deploy can't run different checks. A task that adds a gate adds its step there. From task 07 on, the order is: check → unit → build → Chromium install → PDFs (from task 09) → E2E and axe.
- `npm audit --audit-level=high` runs as a non-blocking report.
- Playwright reports upload as an artifact on failure.
- **The agent must not weaken a gate:** no skipped or deleted tests, lowered thresholds, `continue-on-error`, `@ts-ignore`, or disabled axe rules. Only the task listed above may add a gate. Changing an existing gate needs the owner's approval.

### Workflows

| File | Triggers | Steps |
|---|---|---|
| `pr.yml` | `pull_request` to `main` | The `quality-gate` action. No secrets, cache or deploy |
| `main.yml` | `push` to `main`, `workflow_dispatch`, `workflow_call` | Restore the GitHub data cache → the `quality-gate` action with `GH_GRAPHQL_TOKEN` and `SITE_URL` → `npx wrangler deploy` → `test:smoke` with `SMOKE_BASE_URL` set from `vars.SITE_URL` → save the cache if `source` is `"live"` |
| `nightly.yml` | `schedule: '17 8 * * *'`, `workflow_dispatch` | Calls `main.yml` with `secrets: inherit` |

- `main.yml` and `nightly.yml` are added in task 11, so nothing deploys before then.
- Every workflow sets `permissions: contents: read` and a job timeout.
- `concurrency: { group: production-deploy, cancel-in-progress: false }` goes on the deploy **job** in `main.yml` only. Setting it on the caller too would deadlock.
- The cache key is `github-json-${{ github.run_id }}` with `restore-keys: github-json-`.
- Pass the token to the composite action as an input. Composite actions can't read `secrets`.
- If `vars.SITE_URL` is unset, skip the smoke step with a warning.
- GitHub disables scheduled workflows in public repos after 60 days without activity. Note this in the README.

## Guardrails

- **No invented content.** Anything unknown is a `TODO(owner)` placeholder.
- **No weakened gates**, as listed under [Gates](#gates).
- **No domain or DNS changes.** No `routes`, custom domains or DNS records.
- **No runtime code.** No Worker script, adapter, SSR or live collections.
- **No client-side JavaScript.**
- **No secrets in the repo.** `.gitignore` covers `.env*`, `.dev.vars`, `src/data/github.json`, `dist/`, `.astro/`, `.wrangler/`, `node_modules/`, and test output. Deploys run only from `main.yml`. Do not connect Workers Builds.
- **Confidential work stays generic.** The employer may be named. Its proprietary systems, code, data, hostnames, dashboards and tooling may not appear in text or screenshots.
- **No coursework code** from MS course assignments.
- **No homelab exposure.** Never link to or embed services on the owner's home network.
- **No location metadata in images.** The repo is public, so originals are exposed.
- **People in photos need consent.** Never add identifiable minors.
- **Contact details** are limited to the fields in `site.yaml`. No phone number or address.
- **Pin versions** exactly.
